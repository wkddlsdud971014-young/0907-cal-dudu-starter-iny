# AGENTS.md 에 넣을 규칙 - 책임 경계 (초안, 한얼 확정 대기)

> 목적: 수강생이 **실제 로그인을 받는다.** 다만 실습자가 책임질 수 있는 것만 열고,
> 책임 못 질 것은 에이전트가 만들지 못하게 한다.
> 근거: 5기 `Part8_비즈니스모델/Day06/S4_PIPA_6게이트_biz_matrix.md` 6게이트를
> 에이전트가 실행할 수 있는 금지·강제 목록으로 옮긴 것. 새 규칙 발명이 아니다.

---

## 규칙 A - 이건 만들지 않는다 (요청받아도 거부하고 실습자에게 알린다)

실습자가 "주민번호도 받자", "전화번호 칸 추가해줘" 라고 해도 만들지 않는다.
거부할 때는 이유 한 줄과 대신 할 수 있는 것을 말한다.

| 만들지 않는 것 | 왜 (5기 6게이트) |
|---|---|
| **주민등록번호** 입력칸 | 게이트 5 - 법령 근거 없이 수집 금지. 예외 없음 |
| **전화번호 / 집주소 / 생년월일** 입력칸 | 실습에서 쓸 일이 없는데 유출 시 책임만 남는다 |
| **계좌번호 / 카드번호 / 결제** | 실습자가 책임질 수 없다 |
| **신분증·증빙 사진 업로드** | 위와 같다 |
| **비밀번호를 직접 받아 저장**하는 회원가입 폼 | 구글 로그인이 있는데 굳이 비밀번호를 떠안지 않는다 |
| **만 14세 미만**을 대상으로 한 서비스 | 게이트 4 - 법정대리인 동의가 필요하다 |
| 수집한 이메일로 **광고·홍보 대량 발송** | 게이트 3 - 마케팅 수신 동의를 따로 받아야 한다 |
| 로그인한 사람의 정보를 **외부 서비스로 전송** | 게이트 1 - 제3자 제공 고지 대상이다 |

## 규칙 B - 이건 열어준다 (실제 로그인을 받는다)

- 구글 로그인으로 **실제 사람이 로그인**하는 것
- 구글이 준 것(이메일 / 이름 / 프로필 사진)을 **화면에 보여주는** 것
- 로그인 여부로 화면을 가르는 것
- **본인이 만든 데이터**를 저장·조회·수정·삭제하는 것

이 범위는 실습자가 책임질 수 있다. 구글이 인증을 맡고, 실습자는 자기 데이터만 다룬다.

## 규칙 C - 이건 빠뜨리지 않는다 (없으면 배포 전에 멈춘다)

1. **내 것만 보이게 잠근다.** 표를 만들면 RLS 를 켜고 `auth.uid()` 로 자기 행만 읽고 쓰게 한다.
   정책 없이 `select *` 로 전원 명단이 보이는 화면을 만들지 않는다.
2. **처리방침 한 장**을 화면 아래에 링크로 둔다. 다섯 줄이면 된다 -
   무엇을 받는지 / 왜 받는지 / 언제까지 두는지 / 구글에 인증을 맡긴다는 것 / 문의받을 연락처.
3. **첫 로그인 때 동의 한 번**을 받는다. 구글 로그인은 가입 폼이 없으므로 로그인 직후 화면에서 받는다.
4. **지우는 버튼**을 만든다. 로그인한 사람이 자기 데이터와 계정을 스스로 지울 수 있어야 한다.
5. **로그인 가능한 사람을 정해 둔다.** 구글 동의 화면은 `Testing` 으로 두고
   Test users 에 실습에서 실제로 로그인할 사람만 등록한다. 실습이 끝나면 명단을 비운다.

## 규칙 D - 배포 전 실습자에게 읽어주는 한 줄

"이 주소는 실제로 열립니다. 지금부터 여기 로그인하는 사람의 이메일은 내 Supabase 에 남습니다.
내가 지울 수 있고, 내가 책임집니다."

이 문장을 실습자가 소리 내어 읽기 전에는 공개 주소를 실습방 밖으로 내보내지 않는다.
